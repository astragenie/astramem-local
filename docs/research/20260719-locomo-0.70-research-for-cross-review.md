## 3. Recent improvements (what got us here)
**Measured wins (merged):**
- **#262** — extraction was told to write ISO-8601 dates into atom text; scorer strips punctuation → `2023-05-07` scored 0.0 (93% of 115 temporal answers). Fixed. **This is why temporal went 0.13 → 0.68.**
- **#277** — date-grounding retry: relative expressions → absolute dates inside atom text. Compounds #262.
- **#269** — prompt stopped discarding interpersonal reactions (LoCoMo scores them as gold).
- **#266** — decomposer returned `[]` on 48/48 real queries (`format:json` ≠ JSON array); fixed → multi-hop decomposition actually runs now.
- **#349** — dateless "used to X" cessations written into atom text (not `invalid_at`).
- **compaction OFF for codex** — stage-4 compaction measured net-harmful (typeAcc −23..−29); disabled.
- **chunk 800tok** — beat 1600/3200/12800 in a same-day A/B.
- **#444 (this session)** — embed-index cooperative yield; fixed the event-loop stall / watchdog restart-storm that made long eval runs unreliable (stability, not score).

**Rejected (do NOT re-propose without new evidence — see `20260714-locomo-hypothesis-ledger.md`):** chunk-size as a lever, reranking (~+1 only), raw-transcript search, SQLite swap, sweeper-v1 revert, temperature/maxTokens on codex (dead knobs), named-speaker regex (no-op for LoCoMo).

## 4. Open issues
- **Config levers exhausted** — nothing in the knob-space beats the current baseline.
- **Codex day-variance ±6 pts** — the champion (0.60) is a good-day ceiling, not a floor; a 0.70-capable pipeline would read 0.64–0.70 by luck unless variance is reduced.
- **Answerer is frozen** (Azure gpt-5-mini, k=15) — never tuned. Largest untapped surface.
- **Retrieval rank-ok ceiling is only +7.86** — perfect ranking alone can't reach 0.70; the points must come from extraction/answerer.
- **All tuning is conv-1 (n=199)** — generalisation to full-suite unproven.

## 5. Diagnosis — where the points are, and the ONE thing to measure first
The weak categories are **single-hop (0.49, n=70)** and **multi-hop (0.36, n=32)**. Open-domain (n=13) is too small to chase.

**Single-hop at 0.49 is anomalous** — "the answer is in ONE memory" should be the *easiest* category, yet it scores below temporal. Two mutually-exclusive causes:
- **(a) Retrieval miss** — the gold-supporting atom isn't in top-k.
- **(b) Answerer/format** — the atom *is* retrieved, but the generated answer is shaped wrong and the scorer normalises it to 0.0 (the #262 class, now at the answer layer).

**BET (unmeasured — reviewers, attack this): it's mostly (b).** Rationale: adversarial (0.81) and temporal (0.68) both depend on the same retrieval stack and score well, so retrieval isn't broadly broken; and #262 proved format-scoring-to-0.0 is this project's dominant defect class. If true, the answerer overhaul (§6 Track A) + scorer-format audit (Track B) land hardest exactly where the biggest category is weak.

**THE measurement that settles it (cheap, do first):** for every single-hop question scored <1.0, check whether the gold-supporting atom is in the retrieved top-k. High presence → (b), answerer. Low presence → (a), retrieval. **This single diagnostic picks the entire critical path.**

## 6. Plan to 0.70

**Weighted arithmetic from overall 0.573** (n per category as §2):
| Lever | Move | Overall Δ |
|---|---|---|
| single-hop 0.49 → 0.68 | 70q, biggest | **+0.067** |
| multi-hop 0.36 → 0.55 | 32q | **+0.031** |
| open-domain 0.37 → 0.55 | 13q (noisy) | +0.012 |
| **→ ~0.68**, adversarial/temporal held | | |
| variance-lock + last-mile answerer | | +0.02–0.04 → **~0.70** |

**Tracks:**
- **A — Answerer overhaul (biggest bet).** Currently frozen. Per-category few-shot, exact gold-format output, explicit multi-hop reasoning over top-k, possibly a stronger model. Aimed at single-hop (b) + multi-hop. **Mandatory held-out test split** — an answerer tuned on the eval is worthless.
- **B — Scorer-format co-design.** Generalise #262: catalogue every format the scorer normalises to 0.0 (dates ✓, numbers, names, units, yes/no), make extraction AND answerer emit scorer-friendly text.
- **C — Multi-hop retrieval + reasoning.** #266 fixed decomposition returning `[]`; now ensure decomposed sub-queries surface ALL supporting atoms and the answerer synthesises across them.
- **D — Extraction coverage** (per-session yield 13→10 under variance) — stronger/ensemble extractor (§2.11 ledger "ensemble leans KEEP"), not prompt tweaks.
- **E — Variance-lock** — median-of-3-day runs / more deterministic extraction so 0.70 is *reproducible*, not a lucky day.

**Critical path:** single-hop diagnostic (§5) → if (b): B → A on held-out split → C → D → E. A and B compound (both are format).
