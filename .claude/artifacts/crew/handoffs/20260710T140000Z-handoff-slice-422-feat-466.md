## Objective

Close the 2026-07-10 incident where a sandboxed `init` overwrote the
production daemon's bearer in Windows Credential Manager: the OS
credential-store identity in `src/storage/keystore.ts` was fixed and
machine-global (service `astramem-local`, account `bearer`/`db-key`),
unscoped by APPDATA/configDir sandboxing, so any two installs on the same
machine collided on the same entry.

## Allowed scope

`src/storage/keystore.ts`, `src/storage/bearer-keystore.ts`,
`src/cli/init.ts`, `src/cli/token.ts`, `src/doctor/checks.ts`, and their
tests — entirely inside worktree `w466` on branch
`feat/feat-466-keystore-scope`. Main checkout `C:\work\mega\astramemory-local`
was never touched.

## Forbidden scope

Cloud sync device token (`storeSyncToken`/`readSyncToken`) — left unscoped
intentionally; FEAT-466's ACs cover `storeBearer()`/`getOrCreateKey()` only.
Flagged as a follow-up below.

## What changed

- **Scoped credential-store identity** (`src/storage/keystore.ts`): new
  `scopedService(configDir)` computes `astramem-local:<sha256(configDir)
  .slice(0,16)>`. Both `getOrCreateKey()` (db-key) and `storeBearer()`/
  `readBearer()` (bearer) now write to this scoped identity, with a
  **read-only** fallback to the legacy unscoped identity (`astramem-local`)
  when the scoped one has nothing — no migration write, so old and new code
  can coexist without a re-init.
- **`ASTRA_MEMORY_TEST_FORCE_KEYFILE` extended to the bearer**: previously
  only gated the db-key's file fallback; now `storeBearer`/`readBearer` also
  honor it, writing/reading `<configDir>/bearer.key` (0600 + Windows ACL via
  the existing `restrictKeyFileAcl`) and never constructing an OS credential
  Entry at all when set.
- **`getBearerIdentity(configDir)`** (new export): reports `'scoped' |
  'legacy' | 'key-file' | 'none'` for doctor.
- **Doctor** (`src/doctor/checks.ts`): "Encryption at rest" and "Bearer
  token location" checks now append `identity: scoped|legacy` to their
  messages.
- **Call-site threading**: `storeBearer()`/`readBearer()` now require a
  `configDir` argument (previously implicit/global). Updated `init.ts`
  (already had `configDir` in scope), `token.ts` (`rotateToken` gained an
  optional `configDir` param, defaults to `defaultConfigDir()`),
  `bearer-keystore.ts` (`ResolveBearerOpts.configDir`, defaults to
  `defaultConfigDir()`).

## Safety note

No test in this slice writes to the real OS credential store. All keystore
tests stub `Entry` via the existing `__setEntryCtorForTests` seam (an
in-memory `Map`), and the AC-3/AC-4 tests additionally use a stub whose
constructor throws unconditionally, to prove the bypass path never even
attempts to talk to the real store.

pattern for the db-key, extended symmetrically to the bearer.
