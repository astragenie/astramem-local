## Objective

Build a consolidation semantic-quality eval: >=15 gold-operation fixtures
across 13 scenario categories, run through the REAL `runConsolidation`
(production thresholds, both `candidateSelection` modes), scored with a
weighted-error report, with a machine-readable JSON run artifact and a
correctly-fenced optional LLM-judge follow-on. Tests + fixtures only — no
`src/` changes were needed or made.

## AC-by-AC evidence

- **AC-1** (>=15 fixtures / 13 categories, gold matches actual at production
  thresholds): `describe('AC-1: ...')` — 15 `it.each` cases + one aggregate
  "all 15/15 pass" test + one category-count sanity test. All green.
  Categories present: exact duplicate, paraphrased duplicate, alias
  duplicate, newer-status update, explicit correction, compatible partial
  facts, contradictory unresolved facts, hypothesis later confirmed,
  multiple unique facts (no merge), same-subject/different-predicate,
  same-predicate/different-object, changed preference, completed-vs-planned,
  plus 2 reinforcement fixtures (F14 = AC-7's dedicated 0.91-band case, F15 =
  a second exact-duplicate variant).
- **AC-2** (full vs knn, per-fixture, never averaged):
  `describe('AC-2: ...')` runs `runConsolidation` twice against two
  independent fresh `:memory:` DBs (`candidateSelection: 'full'` then
  `'knn'`, `knnK: 5`), then asserts per-fixture `it.each` equality with a
  message naming the fixture id and both modes' actual outcomes on failure.
  All 15 fixtures identical across modes; knn run also scores 15/15.
- **AC-3** (weighted scoring: false-merge=5, unique-info-deleted=5,
  meaning-reversal=5, wrong-supersede-direction=4, missed-merge=1, printed
  headline numbers + per-category table): `computeWeightedErrorReport()` is
  unit-tested directly against a synthetic 5-mismatch-type fixture list
  (proves the weight math: total=20, per-type counts correct) — decoupled
  from the real run so the weighting logic is exercised even though the real
  15-fixture run scores 0 (by design, since AC-1 requires 15/15 pass). The
  real run's zero-mismatch report is also asserted. `console.table` +
  `console.log` print the category breakdown and headline numbers in
  `beforeAll` — visible in test stdout.
- **AC-4** (baseline artifact for the current threshold pair):
  `scripts/eval/consolidation-bench/results/latest-run.json` is written on
  every test run recording `{mergeThreshold:0.92, proposeThreshold:0.85}`
  plus both modes' full weighted-error reports — verified by reading it back
  in a dedicated test.
- **AC-5** (zero network calls, deterministic): this file never imports or
  constructs an `EmbedProvider`/`LLMProvider` anywhere — every vector is a
  hand-seeded `Float32Array` written straight through
  `SqliteVecStore.upsert`. `runConsolidation` is called with no
  `contradictionDetection`/`judgeProvider` opts, so `resolveContradictionDetection`
  (consolidate.ts) always resolves to "off" — the judge code path inside
  `runConsolidation` itself is never entered.
- **AC-6** (judge pass fenced, opt-in, lives outside the vitest file):
  `describe.skipIf(!JUDGE_OPT_IN)` gates a placeholder block; verified BOTH
  ways — `vitest run` with the var unset shows the block "skipped" (41
  passed, 1 skipped) and with `CONSOLIDATION_EVAL_JUDGE=1` set the block
  runs (42 passed, 0 skipped). The actual judge lives in the new
  `judge-merged-text-quality.mts` skeleton script (correctly fenced,
  verified both unset → no-op message and set → "not yet implemented"
  message — functionality intentionally out of scope this slice per the
  dispatch brief).
- **AC-7** (0.91-band false-merge probe, tilt derived not eyeballed): F14's
  tilt (0.4556) is solved from `cosine = 1/sqrt(1+tilt^2) = 0.91`, and the
  dedicated `describe('AC-7: ...')` block re-derives nothing — it directly
  calls the exported `cosine()` from `consolidate.ts` against F14's own two
  vectors and asserts `toBeCloseTo(0.91, 2)` plus
  `>= proposeThreshold && < mergeThreshold`, so a future accidental edit to
  the fixture or the constant fails loudly instead of silently testing the
  wrong band. Confirms the real run does NOT merge F14 (gold=keep-separate).
- **AC-8** (structured JSON summary, per-category pass/fail, headline
  false-merge/unique-info-loss numbers, machine-readable): same
  `latest-run.json` artifact — `categoryBreakdown` (per scenario category,
  pass/fail counts) and `headline` (`falseMergeCount`, `uniqueInfoLossCount`,

**Environment note (not a code bug, but worth recording):** this shell's
persistent env had `ASTRA_SKIP_CONSOLIDATE=1` set going in — an interactive
shell leftover, not a repo/test artifact. That variable makes
`runConsolidation` an unconditional no-op (kill-switch), and with it set
`tests/consolidate/proposals.test.ts` fails (7 pre-existing tests) with no
change on my part — confirmed by unsetting it and getting a clean 80/83
pass. This is exactly the hazard the dispatch brief called out and the new
eval file's `beforeAll`/`afterAll` guard (save, delete, restore) closes for
itself; other pre-existing test files in the repo don't carry that guard,
so any future dispatch/session should `unset ASTRA_SKIP_CONSOLIDATE` before
trusting a consolidate-suite red/green result in this shell.

## Risks / open questions

- The run artifact (`scripts/eval/consolidation-bench/results/latest-run.json`)
  is regenerated on every test run — parent loop should decide whether to
  commit a checked-in baseline copy (matching extraction-bench's
  `results/real-run-2026-07-08/` convention) or `.gitignore` the directory
  the way `.eval-data/` is ignored. Left uncommitted per dispatch
  instructions ("Do NOT commit — the parent loop owns commits after
  review").
- AC-6's judge script is intentionally non-functional (fencing only, per
  dispatch brief). A follow-up FEAT would wire a real
  `resolveAzureConfig()`/`azureChatComplete()` call reading merged pairs out
  of `latest-run.json` — noted in the script's own header comment.
- Winner-direction determinism for the 5 `supersede` fixtures relies on
  explicit `importance` overrides (0.1 vs 0.9), not on `created_at`
  recency — deliberate, since synchronous same-millisecond inserts in a
  test can tie on recency (mirrors `tests/consolidate/consolidate.test.ts`'s
  own `recordRecallUsed`-based winner-forcing pattern).
