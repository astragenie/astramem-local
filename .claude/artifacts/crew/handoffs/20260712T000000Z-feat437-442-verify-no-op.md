## Residual: bulk_accepted provenance (delivered)

Team lead decision: gap #1 (config validation) accepted as-is; gap #2
(bulk_accepted) scoped in. Implemented in this worktree.

### Design constraint discovered
`MemoryEventRepo.supersede()`'s `provenance?: SupersedeProvenance` param
(src/storage/memory-events.ts, off-limits) hardcodes the payload shape:
passing ANY truthy provenance object sets `payload.auto_accepted = true`
unconditionally and pulls `.threshold`/`.similarity` off it. There is no way
to route a `bulk_accepted` marker through that param without editing
memory-events.ts. Solution: `ProposalRepo.accept()` gained a third, purely
additive `opts?: { bulkAccepted?: boolean }` param. When set, after
`mergeAsSupersede` runs (with no `provenance`, exactly like a plain manual
accept), a new private `markBulkAccepted()` reads back the `supersede` event
`mergeAsSupersede` just appended (`SELECT ... ORDER BY seq DESC LIMIT 1`),
merges `bulk_accepted: true` into its `payload_json`, and writes it back —
all inside the SAME `db.transaction()` `accept()` already wraps everything
in, so no other connection ever observes an intermediate state. This only
touches the `memory_events` TABLE via SQL from `proposals.ts`, not the
`memory-events.ts` FILE or its exported types/migrations.

### Diff summary (all in worktree w437, branch feat/w437-wave2)
- `src/consolidate/proposals.ts`: `ProposalRepo.accept()` gains 3rd param
  `opts?: { bulkAccepted?: boolean }`; new private `markBulkAccepted(loserId)`.
- `src/server/routes/consolidation.ts`: new `AcceptBodySchema` (`{ bulk?:
  boolean }`, optional); `resolveHandler('accept')` now parses `req.body` and
  forwards `{ bulkAccepted: true }` when `bulk === true`. `reject` path
  unchanged (no body parsing added there — no equivalent provenance to mark).
- `src/cli/consolidate.ts`: the `accept` subcommand's per-id loop now sends
  `body: JSON.stringify(all ? { bulk: true } : {})` — only the `--all` path
  sets the flag; a single `accept <id>` still sends `{}`/no marker.
- `tests/consolidate/consolidate.test.ts`: two new tests — (1)
  `ProposalRepo.accept(id, undefined, { bulkAccepted: true })` asserts the
  resulting `supersede` event's payload has `bulk_accepted: true` and NOT
  `auto_accepted`; (2) REST-level `POST /consolidation/proposals/:id/accept`
  with `{ bulk: true }` body asserts the same via `app.inject`.
