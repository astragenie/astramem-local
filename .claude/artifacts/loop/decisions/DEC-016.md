# DEC-016 — Amend the 2026-07-08 graph-memory kill-list entry: build local entity relations (FEAT-481)

## Decision

The 2026-07-08 competitive-matrix entry "Graph memory | entity layer only
(kill-list: full graph) | gap by choice" is AMENDED, not reversed:

- **BUILD** (FEAT-481): local `entity_relations` (bitemporal SPO triples),
  extraction-emitted, plus `get_entity_related` / `get_entity_timeline` MCP
  tools — the local mirror of what the cloud product ALREADY SHIPS in
  production (FEAT-285/M9: `EntityRelationshipEntity`, both MCP tools, mind-map
  dashboard). Operator explicitly accepted the ~5 dev-day spend on 2026-07-13.
- **STILL KILLED**: graph algebra, path queries, community detection,
  graph-native storage engines — the actual "full graph" scope the 2026-07-08
  decision was protecting against.

## Why

The kill-list predated the discovery (2026-07-13 cloud-parity investigation)
that our own cloud already ships the relationship layer. Local building it is
product self-parity + a sync-wire feature, not competitor-chasing. It also
unlocks honest "knowledge graph" positioning currently on the banned-language
list, and Graphiti-class temporal relational queries.

## How to apply

- PM/triage: do not flag FEAT-481 against the kill-list again; cite this DEC.
- The "full graph" kill stays in force for anything beyond FEAT-481's v1
  exclusions — new graph-scope proposals must supersede THIS decision first.
