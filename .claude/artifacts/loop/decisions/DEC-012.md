# DEC-012: Eval resume refuses on any run-params mismatch (no override flag)

## Context

Seeded stratified sampling means a resume launched with a smaller --n
re-derives a strict subset of the original sample: every job replays from the
ledger, zero fresh work happens, and the run reports success at the narrowed
scope with no warning — a silently dishonest published eval number (proven
empirically in the SLICE-422 review: sampleStratified(n=30,seed) ⊂ (n=50,seed),
30/30 overlap).

## Decision

We will persist the scope-determining parameters (dataset path + sha256 content
hash, seed, n, shards, qaPerSample where applicable) to run-params.json on the
first invocation, and hard-refuse (non-zero exit, each differing param named
with original vs current value) any --resume whose parameters mismatch — no
warn-and-continue, no override flag. A run dir without run-params.json
(pre-FEAT-462) refuses with an explicit "predates resume support" message.
Operators wanting different parameters start a fresh run dir.

## Consequences

- positive: a resumed run provably has the same scope as the original; the
  published number cannot be silently narrowed; refusal messages are
  actionable (named params)
- negative: legitimate same-bytes-moved-dataset resumes refuse on path
  mismatch (disclosed strictness); pre-462 run dirs are not resumable
