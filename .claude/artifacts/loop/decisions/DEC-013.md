# DEC-013: FEAT-464 takes the full TypeScript 7 + @types/node 26 major bump

## Context

FEAT-464 (TS toolchain majors) was flagged in the post-v0.15.0 roadmap
handoff (`.claude/artifacts/crew/handoffs/20260712T174500Z-post-v0150-roadmap-waves-handoff.md`)
as blocked on an operator decision, with two viable directions:

- **Pin `@types/node` 20.x** — stay on the Node 20 types the daemon actually
  targets. Much smaller diff, keeps FEAT-464 inside the v0.16.0 hygiene
  release. Defers the TS7 jump to a later dedicated FEAT.
- **Full TS7 + `@types/node` 26** — ~105 test-side type fixes, `bun.lock`
  regen, 4-leg CI verify. Larger blast radius.

The handoff pre-agreed that FEAT-464 slipping past the v0.16.0 checkpoint is
acceptable, and that the work must run SOLO on the shared surface — the
tsconfig/`bun.lock` churn conflicts with any sibling slice touching tests.

## Decision

Take the **full TypeScript 7 + `@types/node` 26 major bump**.

Consequences accepted with the choice:

- FEAT-464 likely **slips past v0.16.0**. v0.16.0 cuts on FEAT-475 + FEAT-474
  (Wave A) alone if 464 is not green in time. This was pre-authorized.
- FEAT-464 runs **solo** on the shared toolchain surface. No sibling slice may
  touch tests, `tsconfig.json`, or `bun.lock` concurrently. It cannot be packed
  into a parallel wave with test-touching work — which notably includes
  FEAT-475 (test-flake fix). Sequence them, do not parallelize.
- Evidence bar: all 4 CI legs green, not just local `tsc --noEmit`. Per repo
  memory (`tsc-noemit-not-build-smoke-fail`), `tsc --noEmit` is NOT a build —
  daemon-spawn smoke tests need a real `bun run build` first or they fail
  spuriously with "exited before printing bound port".

## Alternatives rejected

**Pin `@types/node` 20.x.** Rejected despite being the smaller, safer diff.
Pinning preserves the version skew rather than resolving it, and pays the
migration cost later anyway — with more accumulated test-side drift to fix at
that point, not less. The operator chose to absorb the cost now while the
backlog around it is thin (post-v0.15.0, only four other FEATs open) rather
than during a denser wave.

## Status

Accepted 2026-07-12 by operator decision during post-v0.15.0 roadmap planning.
Supersedes the "OPERATOR DECISION FIRST" open question in the roadmap handoff's
Wave B / slot B1.
