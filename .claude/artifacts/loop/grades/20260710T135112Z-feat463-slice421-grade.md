## Lessons

- Adversarial review briefs with a NAMED attack (suffix decoy) find real leaks
  that AC box-checking misses — both bypass rounds came from explicitly
  instructed attack construction, not general review.
- Heuristic guards on redaction paths must be verified numerically BEFORE
  implementation: the builder's pre-computation disproved one proposed fix
  (label-with-punctuation scores 4.096) and proved the final one
  (0.5 bit/char core separation).
- Placeholder-presence test assertions hide double-match bugs — assert event
  COUNTS. Now structural via expectedEventCount on every fixture.
- Alternations where one branch is a prefix of another (`=` vs `=>`) need
  explicit lookahead guards or they backtrack into spurious matches.
- Entropy detection has an alphabet-class ceiling: digit-only secrets cap at
  ~3.32 bits/char, under the 4.0 threshold — pre-existing, filed FEAT-468.

## Decisions

### DEC-009: Layered entropy-suppression guard (label-core entropy + safe next-token + shape)

**Rationale**: A shape-only guard (round 1) and a next-token-trust guard
(round 2) were both bypassed with reproduced leaks. The accepted design
suppresses entropy detection only when the label CORE (quotes/separator
stripped) is itself below the entropy threshold AND a safe value follows AND
the core is not hex/base62-shaped — an attacker must then use a low-entropy
secret, which is self-defeating.

**Consequences**:
- positive: all 7 reproduced bypass shapes closed; AC-3 false positives stay fixed; residual attack class requires a weak secret by construction
- negative: three-condition guard is more complex than the original; numeric-alphabet secrets remain invisible to the entropy stage (FEAT-468, pre-existing)

## Surprises

- The reviewer's "simplest fix" suggestion was numerically wrong — builder
  caught it by computing before coding.
- The validator found a bug class (double-match output corruption) that three
  review rounds structurally could not see, because review checked family
  non-overlap, not sibling overlap within the new family.

## Followups

- FEAT-468: entropy numeric-secret blind spot (filed).
- Unicode smart-quote label forms: short secrets leak in curly-quoted JSON
  (review LOW, out of scope) — fold into a future redaction FEAT.
- Escaped quotes inside JSON values → partial redaction (disclosed non-goal,
  commented in code).

## What went well

Full gate ladder earned its cost: 3 review rounds + validation caught two
live security bypasses and an output-corruption bug, all fixed and
regression-tested before merge. Suite 2322 → 2360.

## What went wrong

Round-1 guard shipped an under-redaction worse than main — the unplanned
entropy.ts change was under-scrutinized by the builder's own self-verify.
Unplanned changes on security surfaces need the same pre-computation rigor as
planned ones.

## What I would do differently next time

For any redaction/security heuristic: require the numeric-separation evidence
in the FIRST implementation report, not after a review bounce; require event-
count (not presence) assertions from the start.
