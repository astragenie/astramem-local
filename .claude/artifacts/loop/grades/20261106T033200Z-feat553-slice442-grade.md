## Lessons

- `/crew:orchestrate-slice`'s reviewer/verifier dispatch (step 4) could not run from inside this
  wave's Workflow subagent — no `Agent`/`Task` tool was available to spawn `crew:reviewer` or
  `crew:verifier` as separate subagents. The builder fell back to doing both the review and the
  validation itself, inline, per the dispatch instruction's own fallback clause. The fallback was
  executed with real rigor (cold re-read of the diff against the ACs, independent re-derivation of
  AC-2/AC-3 rather than re-running the builder's own assertions) but it is still a same-agent
  self-check, not an independent gate — the ceremony's design assumes an independently-dispatched
  reviewer exists, and for this whole wave it structurally did not.
- A string-only utility function is a clean fit for exhaustive table-driven unit tests: the
  nested-vs-sibling-worktree precedence question was resolved by construction (the two regexes
  are provably disjoint, not just "ordered to avoid collision in the tests we happened to write"),
  which is a stronger reliability guarantee than test coverage alone would give.

## Surprises

- The new nested-rule and the pre-existing FEAT-425 sibling-rule turned out to be mutually
  exclusive by construction (`'worktrees'` can never match the sibling rule's `/^(.+)-worktrees$/`
  regex, which requires a literal `-` before the suffix with at least one preceding character) —
  the review's own "both could apply" test name overstated the actual overlap between the two
  rules, a cosmetic naming nit rather than a substantive gap.

## Followups

- `ASTRA_SKIP_CONSOLIDATE=1` is set somewhere in this box's ambient shell/user profile (outside
  any repo file) and silently degrades consolidation test coverage for anyone running `bun run
  test` without explicitly unsetting it first — flagged again at slice end; worth a permanent
  profile fix or a `docs/memory.md` entry so it isn't rediscovered per-slice (it was rediscovered
  independently in SLICE-444's and SLICE-448's validations too).
- Consider a repo-wide fix for the Workflow-subagent dispatch gap noted above (either give
  Workflow subagents the `Agent`/`Task` tool, or formally downgrade `/crew:orchestrate-slice`'s
  ceremony to "self-review, disclosed" for this execution mode) rather than re-discovering the
  same fallback-and-disclose pattern on every slice in the wave.

## What went well

Scope discipline was exact: exactly the 2 files in `touches_files`, zero scope creep. The
implementation matches the slice's literal spec (last-three-segments rule, nested-before-sibling
precedence, string-only — no `fs`/`child_process`) and both ACs were independently re-derived by
hand-tracing the segment-index arithmetic, not just re-running the builder's own test file. The
`segments.length >= 4` guard was specifically checked for the off-by-one case (bare
`.claude/worktrees/<x>` with nothing before `.claude`) and a dedicated test pins it. Full-suite
noise (95→3 failures across two runs) was root-caused rather than hand-waved: first to the
pre-existing `ASTRA_SKIP_CONSOLIDATE=1` environment leak, then to known Windows watchdog-wrapper
timing flakiness in `tests/service/shim.test.ts`, confirmed unrelated by grepping every
originally-failing file for any reference to the touched function.

## What went wrong

Nothing at the code level. The process-level gap is real: review and validation were both
performed by the same agent that wrote the code, because no independent reviewer/verifier
subagent could be dispatched in this execution mode. That gap did not cause a missed defect here
(this slice is small and the fallback review was unusually thorough), but it is the same
structural gap that let real defects through on SLICE-445 and SLICE-448 later in this wave.

## What I would do differently next time

Flag the Workflow-subagent dispatch limitation at the start of the wave rather than at the end of
each slice — it was independently rediscovered and disclosed five separate times (442, 443, 444,
445, 448) instead of being called out once as a wave-level risk before SLICE-443 ever started.
