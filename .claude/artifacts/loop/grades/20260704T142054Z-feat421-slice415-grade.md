## Lessons

- "Dispatched run = hard gate" caught THREE workflow bugs YAML review never
  would: actions/cache implicit post-save skips on red jobs (this lane is
  red-by-design when drift exists → cache would never save); docker exec
  pulls break when reusing a host Ollama singleton; container-root-owned
  files in a bind mount fail the unprivileged cache-save tar (warning-level,
  silent).
- The lane paid for itself before merging: two real drift findings (stale
  nomic-768 model literal in ollama-embed live test; 30s poll too tight for
  real CPU LLM inference in plugin-flow e2e) — issue #50.
- workflow_dispatch can't target a workflow that exists only on a
  non-default branch — temporary branch-scoped push trigger is the pattern,
  with removal as an explicit AC step.
- The org's "5 runners" are 5 job slots on ONE EC2 host — anything shared
  (Ollama daemon, docker images, caches) must be treated as a host singleton
  with a workflow concurrency group.

## Decisions

### DEC-007: Nightly lane is red-by-design; issue #50 is the signal

**Rationale**: The lane exists to surface real-provider drift, so a red run is
the expected productive outcome, never a merge blocker (schedule + dispatch
only; PR CI untouched). Signal is a single pinned issue updated in place —
never duplicated — so red has one owner-visible home.

**Consequences**:
- positive: drift surfaces nightly with failing test names; zero PR friction
- negative: someone must actually triage issue #50 or the lane rots like most
  nightly CI (README names the triage expectation)

## Surprises

- Run 4's restore/pulls steps skipped themselves because the run-3 container
  was still serving on the shared host — the singleton-reuse path got
  exercised for free, proving the probe logic.

## Followups

- Issue #50 findings need owners: update the nomic literal in
  tests/providers/ollama-embed.test.ts (one-liner) and widen/gate the
  plugin-flow e2e poll for CPU inference. Neither filed as FEAT — small
  enough for a review-debt batch (FEAT-417 territory, other session).

## What went well

Iterative real-run verification loop (4 runs) converged fast; each red run
produced a concrete fix. Issue automation proven on genuine failures, not
dry-runs. Cold timing 3m58s — a quarter of the 15min budget.

## What went wrong

Session-close pressure meant the orchestrator wrote the closing artifacts
inline from run evidence rather than a fully independent reviewer pass —
acceptable for a CI-only diff with four live runs as evidence, noted for
transparency.

## What I would do differently next time

Bake "actions/cache save-on-red" and "container-root file ownership" into a
CI-workflow checklist — both are silent-failure classes that only surface by
inspecting a real run's artifacts.
