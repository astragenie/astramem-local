## Decisions

### DEC-001: Clamp at serialization, keep internal telemetry raw

**Rationale**: recordRecallServed feeds the ADR-010 usefulness log (memory_events),
an internal diagnostic surface — keeping the raw pre-clamp value preserves the
evidence of WHICH threshold was breached, while every client-facing wire boundary
(REST + MCP) ships only in-contract [0,1] values.

**Consequences**:
- positive: contract violations remain diagnosable from the events log after clamping
- negative: two representations of the same score exist transiently; anyone
  cross-referencing telemetry against wire captures must know clamping happens later

### DEC-002: Reference-identity passthrough on in-contract items

**Rationale**: clampScores returns the same object reference when the score is
already in contract, so the happy path allocates nothing and stays bit-identical —
cheap insurance must be free where it does not fire.

**Consequences**:
- positive: zero perf/GC cost and zero behavioral diff on the normal path
- negative: mutating the returned array items would alias the originals (acceptable — responses are serialize-and-forget)
