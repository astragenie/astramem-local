## Lessons

- Prompt-size changes are infra changes: v3's ~3.8k-token system prompt
  silently exceeded Ollama's default 4096 num_ctx (the provider never set
  it), collapsing recall 3 atoms → 1. The reviewer caught it as HIGH by
  reasoning about token budgets, not by reading diffs. Any future prompt
  growth must re-check provider context budgets.
- Object-spread of the same key is a silent replace, not a merge: two
  conditional spreads both producing a top-level `options` key meant
  `num_predict` silently clobbered `temperature` on every call passing both —
  which was every production call site (05-extract, 04-compact,
  extract-entities). Found unprompted by the builder while fixing num_ctx,
  proven against git HEAD.
- Live verification on a VRAM-saturated box surfaced the operational cost of
  dynamic num_ctx: values differing from the resident model force Ollama
  reloads which can fail loudly (ECONNRESET + eviction) near the VRAM
  ceiling. Loud beats silent truncation; bucketed num_ctx (4096/8192/16384)
  filed as SLICE-436 follow-up candidate.
- Shipped via branch-PR from the shared main checkout with a concurrent
  unrelated change (dev-noauth) in the same working tree: pathspec-scoped
  commits on separate branches worked with zero collision — but only because
  file-set disjointness was verified first.

## Surprises

- The temperature-clobber bug — a config value everyone believed was applied
  had never reached Ollama in production. Extraction quality baselines
  measured before this slice were all at model-default temperature.
- Fresh IDE diagnostics claimed extractProfile fixture type errors mid-flight;
  tsc was clean. Second occurrence of the stale-diagnostics class (SLICE-432
  grade recorded the first) — trust tsc, not the diagnostics pane, during
  concurrent-builder churn.

## Followups

- Bucketed num_ctx (4096/8192/16384) to avoid same-bucket model reloads on
  VRAM-tight boxes — SLICE-436 candidate.
- Context-budget assertion in tests whenever a prompt grows (estimated tokens
  vs provider window) — adopt as standing practice.
- Extraction-quality baselines predating this slice ran at wrong temperature;
  SLICE-436's 4-config proof phase supersedes them.

## What went well

HIGH fix verified live against real Ollama with the money assertion (both
gold atoms restored, rich 300-800ch shape matching gold); builder found and
fixed a second real production bug unprompted with proof against git HEAD;
PR + auto-merge pipeline worked end-to-end (#164).

## What went wrong

First builder pass shipped the v3 prompt without checking the provider
context budget — the recall regression was only caught in review. Three CI
flake re-run cycles (self-hosted runner-5 poisoned workdir, EACCES class)
delayed merges.

## What I would do differently next time

When a slice grows any prompt or payload, include a context-budget assertion
in its tests up front, not as a review catch.
