## Lessons

- Exhaustive fixture design pays: AC-1's "build every field non-default, never
  start from defaultConfig()" requirement caught a 6th dropped field
  (search.governance.maxComponentWeight) that filer + PM evidence both missed.
- First array-typed Config field is a compatibility event, not just a feature:
  adding YAML flow-sequence emit created a rollback crash on older loaders.
  Any new value SHAPE in config.yaml needs a downgrade check against the
  previous release's loader.
- Structural key-diff guards (AC-2/AC-3) need the "nothing to emit" concept
  from day one: undefined-valued optional keys and empty arrays are legal
  omissions; two fix rounds were spent teaching the check that.
- Validator running real `init` collided with the machine-global OS credential
  store and overwrote the production bearer (recovered, zero impact) —
  sandboxing APPDATA does not sandbox the keystore. FEAT-466 filed.

## Decisions

### DEC-008: Omit-when-empty for array-typed config fields

**Rationale**: A pre-FEAT-461 loader parses a flow-sequence line as a literal
string, which crashes the redact path after `reinstall --rollback`. Omitting
the line when the array is empty keeps default configs byte-compatible with
every prior loader; only users who explicitly set customPatterns carry a
documented manual step before rollback.

**Consequences**:
- positive: rollback safe for the default case; no YAML library dependency
- negative: non-empty customPatterns + rollback still needs a manual line
  removal (documented in CHANGELOG); findMissingConfigKeys needed an
  "empty array = nothing to emit" carve-out

## Surprises

- The FEAT's own evidence section (PM-verified same day) still undercounted
  the dropped fields — only an exhaustive generated fixture surfaced the last one.
- Sandboxed validation can mutate machine-global state (Windows Credential
  Manager) despite full APPDATA/LOCALAPPDATA isolation.

## Followups

- FEAT-465: loader comment-stripping corrupts ` #` inside quoted strings /
  flow sequences (pre-existing, newly user-reachable via customPatterns).
- FEAT-466: scope OS-keystore identity per config dir or add bearer keyfile
  test bypass (production-credential collision incident).
- LOW residual from re-review: hasNothingToEmit doesn't treat explicit `''`
  like the emitter's truthy-omit does — one spurious warn possible in a
  scenario no normal path produces; fold into FEAT-465 or fix opportunistically.

## What went well

Gate ladder worked exactly as designed: builder self-verified green, reviewer
found a real HIGH (reproduced end-to-end, not theoretical), validator found a
real operational incident + a UX-noise bug, both fixed before merge. Full
suite grew 2322 → 2330 with zero failures.

## What went wrong

Two extra fix rounds that better up-front design would have avoided: the
rollback hazard (new value shape not checked against old loader) and the
false-positive warn (key-presence vs value-defined confusion). The keystore
incident should never have been reachable from a sandboxed run.

## What I would do differently next time

Add a "downgrade/rollback compatibility" bullet to review focus for any
config-format or on-disk-shape change by default; forbid validators from
running real `init` until FEAT-466 ships (use ASTRA_MEMORY_TOKEN).
