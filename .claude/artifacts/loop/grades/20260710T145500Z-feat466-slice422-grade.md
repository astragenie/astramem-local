## Lessons

- Scoping a shared-namespace identity creates a rollback trap by construction:
  the first scoped release is always one rollback away from a binary that only
  knows the unscoped name. Any identity migration needs an explicit
  old-binary-resolution-order simulation test (simulateOldBinaryResolve
  pattern, verified against `git show` of the actual old source).
- "Read-only fallback" contracts need a named exception list — rotation is the
  moment stale legacy state becomes dangerous, so rotate write-through is the
  correct, contained exception; init write-through is the incident vector.
- Wave-1 worktree parallelism: per-worktree slice-ID counters collide (three
  SLICE-422s); telemetry files union-merge fine but the grade/ceremony tooling
  keys on slice id — needs per-worktree id offsets or feature-suffixed ids.
- Validator methodology matured: cmdkey baseline + 4 checkpoint diffs +
  readBearer value check = byte-level proof the real store was untouched.

## What went well

fall-through) that unit tests structurally couldn't see; validator proved the

## What went wrong

order — the rollback interaction was between this slice's change and
pre-existing SEC-10 logic two files away.

## What I would do differently next time

FIRST (before the migration code), same way FEAT-463 learned to pre-compute
entropy numbers.
