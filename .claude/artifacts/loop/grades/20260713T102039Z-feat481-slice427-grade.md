## Lessons

- A JS numeric constant interpolated into SQL silently round-trips through a
  double: `9223372036854775807` rendered as `9223372036854776000` in the SQL
  text. House convention (entities.ts) inlines int64-max as literal SQL text —
  follow it; never hoist SQL sentinels into JS number constants.
- Two reviewers with different lenses paid off again: typescript-reviewer
  caught the sentinel; correctness reviewer independently proved it inert but
  divergent-from-convention — same finding, complementary framing.
- Validation dodged the keystore-global-identity collision (spawned daemon
  resolves its encryption key from the OS credential store, NOT scoped by
  ASTRA_MEMORY_DATADIR) by doing the erase scenario in-process. The trap from
  the FEAT-466 memory is still live for any test that spawns a daemon against
  a temp datadir.
