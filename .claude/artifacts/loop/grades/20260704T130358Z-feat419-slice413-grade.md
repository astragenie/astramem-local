## Lessons

- better-sqlite3 + Node run-to-completion makes any zero-await
  db.transaction() closure a true critical section across real sockets —
  before hypothesizing a race, grep for awaits INSIDE the transaction, not
  around it. The preflight hypothesis died on this.
- Mock-LLM canned outputs collide across distinct inputs → the dedup stage
  correctly collapses them; concurrency assertions must be dedup-agnostic
  (assert job completion states, not memories_created).
- "Byte-identical replay responses" is the wrong idempotency contract wording
  — one creator (idempotent:false) + k-1 replays (idempotent:true) sharing one
  real id is the actual, already-pinned contract shape.

## Decisions

### DEC-003: Ship tests-only; record refuted hypothesis in the plan

**Rationale**: All three concurrency scenarios were green first-run; code
reading (builder + independent reviewer) confirmed the claim→finalize sequence
is atomic inside one synchronous transaction on both ingest paths. Landing a
"fix" for a non-existent race would add complexity with zero benefit.

**Consequences**:
- positive: permanent regression net for the idempotency path; documented
  refutation (plan addendum + test header) prevents re-investigation
- negative: none material — if the transaction shape ever changes (an await
  slips in), these tests are the tripwire

## Surprises

- The hypothesized race window simply does not exist in this code shape — the
  entire claim→finalize is one synchronous transaction (ingest.ts:412-492 and
  :296-332), verified twice independently.

## Followups

- None. Unrelated parallel-load flake observed once in
  tests/security/encryption.test.ts (green in isolation) — same shape as the
  documented init.test.ts flake; note only, no ticket.

## What went well

Preflight plan gave the builder precise targets; builder correctly refused to
manufacture a fix when tests came up green and distinguished its own test-design
bug (dedup-unaware assertion) from product behavior. Reviewer verified the
no-race claim from source, not from the builder's comments.

## What went wrong

The preflight hypothesis itself was wrong — I read the claim/finalize call
sites as spanning an await window without checking they sit inside one
transaction closure. Cost: none this time (the tests are valuable regardless),
but a fix-first dispatch would have wasted a builder run.

## What I would do differently next time

When hypothesizing concurrency bugs in better-sqlite3 code, trace the
transaction boundaries FIRST — the hypothesis is only viable if an await sits
inside the critical section.
